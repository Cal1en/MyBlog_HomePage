# 视差遮蔽映射`Parallax Occlusion Mapping`
我们在第 5 章中曾提到过 POM 技术，由于这次场景中的地面使用的是砖块材质，因此自然需要明显的高低差。我们将使用`Parallax Occlusion Mapping`来直接获得偏移后的`uv`坐标，然后对各类贴图采样。

# 雨天的路面
显然雨天的路面会有积水，而积水显然会优先填满砖块的缝隙，也就是低处，因此我们可以通过`Height Lerp`配合顶点色与高度图来完成两者之间的过渡。我们将顶点色的`RGB`分量分别使用`Height Lerp`计算后得到的结果命名为`RChannelLerp`、`GChannelLerp`、`BChannelLerp`。

## `RChannelLerp`雨水颜色 表面积水
我们使用`RChannelLerp`作为雨水颜色的插值因子，同时雨水的颜色还和雨水的深度有关，因此我们需要做两次插值处理。

# 水面法线
水面法线的采样方式与前几章一致，也就是用不同的`Tilling`和`Speed`采样两次同一张法线贴图，我们此处不再赘述。

但需要注意的是，我们不能使用前面通过 POM 计算出来的`uv`对法线贴图进行采样，毕竟 POM 是为了使得物体表面看上去有高低差，但是水面的法线应当是平整的，因此此处我们将直接使用世界空间坐标的`xz`分量进行采样。

# 水面雨滴
我们可以使用序列帧动画来循环播放水面雨滴落下的法线效果，`ASE`自带了`Flipbook uv Animation`节点用于播放动画，我们依然选择传入世界空间坐标的`xz`分量，但是由于我们的雨滴使用的是序列帧动画，如果直接使用`Tilling`值来控制`uv`缩放的话，那么雨滴法线序列帧贴图在平铺模式下，超出$[0,1]$的部分可能将没有办法读取到完整的序列帧贴图，换句话说，我们必须保证水面上的每一个部分都能完整读取整张水滴法线序列帧贴图，因此我们将使用`frac`节点来获取世界空间坐标的小数部分，也就是将水面分成许多个$[0,1)$的小区间，然后在每个小区间上完整播放序列帧动画。

## `Spherical Projection`球面投影
我们使用`IBL`之类的与`CubeMap`相关的技术的时候，在采样`CubeMap`时，传统的采样方法是根据表面法线方向`Normal`以及视线`viewDir`方向计算出反射方向`reflectDir`，然后通过反射方向来采样`CubeMap`，但是这种采样方式最大的缺点是，**采样的结果只和反射方向有关，与物体在空间中的位置无关**。比如房间内的地板能够反射房间内的环境，如果我们走进房间的同时始终保持同一个角度看向地板，那么我们看到的反射结果始终是保持不变的，**这显然是错误的**。

由此，我们首先引入了球面投影`Spherical Projection`，其最主要的目的是将当前的反射点位置也参与到计算过程中，如下图所示：

<!-- 这是一张图片，ocr 内容为： -->
![](/img/Kerry/23_霓虹街道/1779084573190-fb860872-8da2-4023-a8cc-fc9a7e94d2fb.png)

我们在空间中创建了一个临时的包围球，该包围球的位置与大小始终不变，而当前顶点`V`可以是`Reflective surface`上的任意点，**反射向量与包围球的交点**`P`**实际指代的是反射向量与当前周边环境的交点**，由此我们可以看出，哪怕视线方向`viewDir`始终不变，我们看向`Reflective surface`上的不同点时，反射向量与包围球（环境）的交点也会不断发生变化。

既然我们已经获得了当前反射向量与环境的交点，那么我们只需要在`CubeMap`中找到这一点即可。通常来说，我们只需要保证`CubeMap`在烘焙/拍摄的时候中心点与`Bounding Sphere`的中心点保持一致，那么我们只需要直接从中心点指向`P`点，就能够获得用于采样的反射向量。

上述方式也正是 Unity 内置管线中反射探针的默认采样方式，`CubeMap`以及`Bounding Sphere`的中心点都位于反射探针的位置，我们也可以调整反射探针中的`盒偏移`等相关设置来调整`Bounding Sphere`的中心位置与大小。

但是这种方法存在着明显的缺陷：我们用包围球来模拟周围的环境，如果当前环境位于室外，那么包围球可以很好的模拟天空盒的效果，但是如果当前环境位于室内，显然我们不能直接使用球体来近似立方体，这导致我们的渲染结果会出现画面上的扭曲，由此，我们引入了`Box Projection`盒投影。

## `Box Projection`盒投影
盒投影的基本原理基本与球面投影保持一致，区别在于我们将`Bounding Sphere`替换为了`Bounding Box/Volume`，如下图所示：

## 代码实现
在一开始，我们的已知量为`viewDirWS`，`normalWS`以及`reflectDirWS`，同时，我们使用`AABB`包围盒的形式来表示`Bounding volume`，即通过`_BBoxMax`和`_BBoxMin`来表示`Bounding volume`中距离中心最远的两个顶点。

那么显然，我们需要求出真正用于采样`CubeMap`的反射向量，该向量需要通过`reflectDir`与`Bounding volume`的交点`P`求出，由此，我们可以这样表示`P`点的坐标：

$$ P(t) = localPosWS + t \times reflectDirWS $$

其中`t`表示从`localPosWS`（即`V`点）出发，沿着`reflectDirWS`行进的距离（比例）。

那么接下来我们就要想办法求出`t`。

在 Unity 内置管线中，我们会发现，反射探针的`Bounding Volume`是没有办法旋转的，也就是说`Bounding Volume`将始终与世界空间坐标系的`xyz`轴平行。由此，我们可以使用世界空间坐标的`XMax`、`XMin`、`YMax`、`YMin`、`ZMax`、`ZMin`来分别表示`Bounding Volume`的六个面，也就是`_BBoxMax`和`_BBoxMin`的各自的分量。

我们假设当前`P`点落在`XMax`面上。由于`Bounding Volume`与世界空间坐标系平行，那么`XMax`面上所有点的`x`分量均等于`XMax`，即`_BBoxMax.x`，`P`点也不例外，由此我们可以得到：

$$ {P(t)}_x^{Max} = {localPosWS}_x + t \times {reflectDirWS}_x = {\_BBoxMax}_x $$

由此我们就可以求出`XMax`面对应的`t`：

$$ t_{XMax} = \frac{{\_BBoxMax}_x - {localPosWS}_x}{{reflectDirWS}_x} $$

同理我们还可以求出在`xyz`轴正方向上的另外两个面所对应的`t`：

$$ t_{YMax} = \frac{{\_BBoxMax}_y - {localPosWS}_y}{{reflectDirWS}_y} $$

$$ t_{ZMax} = \frac{{\_BBoxMax}_z - {localPosWS}_z}{{reflectDirWS}_z} $$

对剩下的三个面来说，同理也有：

$$ t_{XMin} = \frac{{\_BBoxMin}_x - {localPosWS}_x}{{reflectDirWS}_x} $$

$$ t_{YMin} = \frac{{\_BBoxMin}_y - {localPosWS}_y}{{reflectDirWS}_y} $$

$$ t_{ZMin} = \frac{{\_BBoxMin}_z - {localPosWS}_z}{{reflectDirWS}_z} $$

由几何关系可以得出，`t`指代的是从`localPosWS`出发，在`reflectDirWS`方向上行进的距离，那么显然，不管当前的`P`点位于哪个平面上，从`localPosWS`出发沿着`reflectDirWS`方向的这条射线肯定会与至少一个`Bounding Volume`的面相交，而我们要求的`P`点自然就是**该射线与最先相交的平面形成的交点**，因此我们只需要计算出上述`t`的**最小值**即可。

但是我们会发现，如果当前的面位于`reflectDirWS`的负方向的话，那么`t`将会是**负值**，显然这些位于反方向上的面可以直接被排除，显然由于立方体中心对称的特性，如果当前的`P`位于`XMax`，那么`txmin`一定是负值，其余情况同理，所以我们可以先对`(txmax, txmin)`、`(tymax, tymin)`、`(tzmax, tzmin)`分别取`max`来**去除负值**，然后再在剩下的三个`t`值中**取最小值**，即可求出`P`点的坐标。最后我们只需要使用`P`点坐标减去`CubeMap`的中心点即可获得最终的反射向量。

```csharp
float4 frag(vertexOutput input) : COLOR
{
    float4 reflColor = float4(1, 1, 0, 0);
    // Find reflected vector in WS.
    float3 viewDirWS = normalize(input.viewDirInWorld); 
    float3 normalWS = normalize(input.normalInWorld);
    float3 reflDirWS = reflect(viewDirWS, normalWS);                        
    // Working in World Coordinate System.
    float3 localPosWS = input.vertexInWorld;
    float3 intersectMaxPointPlanes = (_BBoxMax - localPosWS) / reflDirWS;
    float3 intersectMinPointPlanes = (_BBoxMin - localPosWS) / reflDirWS;
    // Looking only for intersections in the forward direction of the ray.  
    float3 largestParams = max(intersectMaxPointPlanes, intersectMinPointPlanes);
    // Smallest value of the ray parameters gives us the intersection.
    float distToIntersect = min(min(largestParams.x, largestParams.y), largestParams.z);
    // Find the position of the intersection point.
    float3 intersectPositionWS = localPosWS + reflDirWS * distToIntersect;
    // Get local corrected reflection vector.
    Float3 localCorrReflDirWS = intersectPositionWS - _EnviCubeMapPos;
    // Lookup the environment reflection texture with the right vector.             
    reflColor = texCUBE(_Cube, localCorrReflDirWS);
    // Lookup the texture color.
    float4 texColor = tex2D(_MainTex, float2(input.tex));
    return _AmbientColor + texColor * _ReflAmount * reflColor;
}
```

## 进一步修改
在 Unity 中，我们可能只会在反射探针中见到`Box Projection`技术，但实际上这种技术也特别适合用来创造空间感，比如街边的商店，我们只需要给上一张商店内部的`CubeMap`，就可以通过`Box Projection`技术在一张平面上展现出商店内部的构造，但是我们只使用上述代码的话，当我们的面片的大小和`Bounding Volume`的大小不一致的话，在面片的四周会出现扭曲，为了去除这种扭曲，我们可以使用`Box Mask`节点，其原理类似我们之前经常使用的`Sphere Mask`，只不过这次将球体换成了立方体。
