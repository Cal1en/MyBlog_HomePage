# 全局变量
`Shader`同样拥有全局变量，我们可以在`Shader`中手动指定变量类型为`Global`，`Global`类型的变量无法在材质球`Inspector`面板中找到，**必须使用`C#`脚本来赋值**。我们可以通过`Shader.SetGlobal`类型的函数来根据变量名指定`Shader`中`Global`类型的属性值。该函数调用后，所有具有该属性值的`Shader`/材质球均会接收到该值（前提是设置为`Global`变量）。

{% note danger %}
设置为`Global`之后，**变量名称前将不再带有下划线**`_`

{% endnote %}

在`ShaderLab`中，如果我们希望当前的变量为全局变量的话，我们只需要将该变量从`Properties`中删除即可。

## `Auto-Register`
在先前的`ASE`使用过程中我们不难发现，**如果当前的一系列节点最终并没有连接到表面着色器的节点上，那么这一系列节点中的`Properties`都不会显示在材质球面板中，因为`ASE`并不会将这些未使用的变量写入`Shader`代码中**。在本章节第5节中我们将讲到使用函数调用全局变量，此时我们并不需要将全局变量连接到`Custom Expression`节点，那这也就意味着这些全局变量并不会被写入`Shader`代码中，为了能够正常调用这些全局变量，**我们需要勾选这些变量左侧面板中的`Auto-Register`选项，这样一来`ASE`就会始终将这些变量写入代码中**。

# `[ExecuteInEditMode()]`
即使加了上述标签，`FixedUpdate`函数依然不会在编辑器模式下工作，因为`FixedUpdate`和物理引擎绑定，而编辑器模式下物理引擎并不会运行。

# 粒子系统
我们需要模拟护盾受到撞击后表面沿撞击点向外扩散的波纹效果，该波纹的传播速度先快后慢，因此我们可以**利用粒子系统的生命周期函数和生命周期曲线来实现**。我们只需要使用`C#`脚本获取粒子系统，以及利用**射线检测**获取鼠标点击位置和护盾表面的交点（撞击点），然后控制粒子系统在该位置处**发射一颗粒子**，并**将该粒子的大小以及位置通过脚本传参的方式传递给`Shader`** 即可，然后`Shader`就可以通过类似溶解算法渲染撞击点周围扩散波纹的效果。

{% note danger %}
之所以传递的是粒子的位置而不是粒子发射器的位置，是因为我们后续需要通过当前传入的位置来判断当前使用的是哪颗粒子，我们会在本章第7节中讲到。

{% endnote %}

+ `模拟空间`：该选项指的是粒子发射之后粒子的空间位置是相对于粒子发射器还是世界空间，即粒子会不会跟随粒子发射器移动。
+ `起始生命周期`：即粒子的存活时间，此处也指波纹扩散的持续时间。
+ `生命周期内大小`：即粒子的大小随时间变化的曲线。
+ `发射`：由于我们希望粒子停留在撞击点，因此我们需要关闭该选项。
+ `形状`：指的是发射的方向，即发射的粒子宏观上形成的形状，该选项会导致粒子生成在一定的随机范围内，因此也需要关闭。

# `Custom Expression`
我们现在一次性只能添加一个冲击波，如果我们想要实现**多个冲击波同时渲染**，那我们就需要循环调用上述代码，也就是说，我们每点击一次护盾，就将此次点击的位置以及此次生成的粒子的大小传递进`Shader`，但是我们还需要保证在粒子的生命周期内，我们始终使用该粒子的参数参与计算，而不是其他次点击时传入的粒子参数，而我们又需要实现多个冲击波同时渲染。因此，我们需要使用**数组**来按产生时间顺序逐个存储粒子的位置以及它们当前时刻的大小，并按顺序依次将它们代入上述代码，从而构成循环。

（**本质上就是每个粒子都各自对应一段上述的代码，由于代码结构相同，因此我们可以将数组序号作为循环因子来构建循环**）

由于直接复制多次节点不够美观，我们将使用`Custom Expression`节点来将上述节点封装成一个函数。该节点需要我们将函数体从节点手动翻译成代码。

```csharp
float hitResult = 0;
for(int j = 0; j < AffectorAmount; j++)
{
    float distanceMask = distance(HitPosition[j], WorldPos);
    float hitMask = saturate((1 - distanceMask / HitFadeDistance) * HitFadePower);
    float2 uv_Ramp = float2(-clamp((distanceMask - HitSize[j] + HitNoise) / HitSpread, -1, 0), 0.5);
    float hitWave = tex2D(RampTex, uv_Ramp).r * hitMask;
    hitResult += hitWave;
}
return saturate(hitResult);
```

**函数的输入参数需要在左侧面板中手动指定**，与其他语言中的全局变量一样，我们并不需要向函数传入全局变量，只需要在函数内使用该全局变量名即可。

将上述代码填入`Custom Expression`中后，`Shader`中的代码如下：

```csharp
float HitWaveFunction( float3 WorldPos, float HitFadeDistance, float HitFadePower, float HitSpread, float HitNoise, sampler2D RampTex )
{
    float hitResult = 0;
    for(int j = 0; j < AffectorAmount; j++)
    {
        float distanceMask = distance(HitPosition[j], WorldPos);
        float hitMask = saturate((1 - distanceMask / HitFadeDistance) * HitFadePower);
        float2 uv_Ramp = float2(-clamp((distanceMask - HitSize[j] + HitNoise) / HitSpread, -1, 0), 0.5);
        float hitWave = tex2D(RampTex, uv_Ramp).r * hitMask;
        hitResult += hitWave;
    }
    return saturate(hitResult);
}
```

不难发现，虽然`ASE`会帮我们将这段代码封装成函数，但是并不会帮我们填写返回语句，毕竟`ASE`也不知道我们最终想要输出什么结果。因此**我们需要手动将`return`语句写入代码中**。

```csharp
using System.Collections;
using System.Collections.Generic;
using UnityEngine;

[ExecuteInEditMode()]
public class CS12_ForceField : MonoBehaviour
{
    [SerializeField] private ParticleSystem particleSystem;
    [SerializeField] private GameObject forceField;
    [SerializeField] private int maxParticles;
    [SerializeField] private float maxSize;
    private ParticleSystem.Particle[] particles;
    private Vector4[] positions;
    private float[] sizes;

    private void Start()
    {
        //particleSystem.main为结构体 不是引用类型
        //因此需要使用以下特殊方式修改
        //var main中包含一个指向particleSystem.main的指针
        //因此可以使用类似引用的方式修改
        var main = particleSystem.main;
        //修改粒子上限
        main.maxParticles = maxParticles;
        //修改粒子大小
        main.startSize = maxSize;

        //初始化
        particles = new ParticleSystem.Particle[maxParticles];
        positions = new Vector4[maxParticles];
        sizes = new float[maxParticles];
    }
    private void Update()
    {
        if (Input.GetMouseButtonDown(0))
        {
            Ray ray = Camera.main.ScreenPointToRay(Input.mousePosition);

            if(Physics.Raycast(ray, out RaycastHit hit, 100) && hit.transform == forceField.transform)
            {
                //hit.point 碰撞点; hit.transform 碰撞到的物体的transform
                particleSystem.transform.position = hit.point;
                //发射一颗粒子
                particleSystem.Emit(1);
            }
        }

        //防止在编辑器模式下报错
        if (particles != null)
        {
            //ParticleSystem.Particle为结构体 不是引用类型
            //因此我们每一帧都需要重新获取粒子的信息
            int affectorAmount = particleSystem.GetParticles(particles);

            //GetParticles的返回值为当前存活粒子的数量
            if (affectorAmount == 0)
            {
                //如果当前没有粒子了，就关闭下半部分的代码 节约性能
                //如果需要让最后一次生成的冲击波完全消失就注释掉return
                return;
            }

            for (int i = 0; i < affectorAmount; i++)
            {
                //存储数组
                positions[i] = particles[i].position;
                sizes[i] = particles[i].GetCurrentSize(particleSystem);
            }

            //传递全局变量
            Shader.SetGlobalFloat("AffectorAmount", affectorAmount);
            Shader.SetGlobalVectorArray("HitPosition", positions);
            Shader.SetGlobalFloatArray("HitSize", sizes);
        }
    }
}
```

# 三平面映射和`uv`采样的区别
使用`uv`来直接采样贴图时，显然采样的纹理的位置之和模型的`uv`有关，模型在世界空间中移动时贴图会一直跟随模型位置，但是使用三平面映射时，我们会使用当前物体的世界空间坐标的`xy`、`yz`、`xz`分别采样物体，这也就意味着采样的结果和物体在世界空间中的位置有关，物体在移动时，贴图采样的结果依然会“留在原地”，也就是留在原先的位置，并不会跟随物体一起移动。

# 流光效果
## `FlowMap`和`Flow`节点
我们将使用`ASE`自带的`Flow`节点和`FlowMap`制作流光效果，其原理在于，**`FlowMap`的`rg`通道存储着`uv`随时间不断变化的扭曲方向**，我们使用扭曲后的`uv`对流光贴图进行采样，即可获得表面不断变化扭曲的流光效果。

需要注意的是：`FlowMap`的`rg`通道默认**用0.5表示静止，0表示朝左下方移动，1表示朝右上方移动**，但是**早期的`Flow`节点中有错误**，如下图所示：

<!-- 这是一张图片，ocr 内容为： -->
![](/img/Kerry/16_力场护盾/1778331749359-f49b1e68-a999-4c24-b59d-1f9949256bfc.png)

`Flow`节点源码中写到，在我们没有传入`Flow Direction`时，`Flow`节点将会使用顶点色`Vertex Color`的`RG`通道作为扭曲方向，`Flow`节点会将该二维向量取负再加`0.5`，即从$ [0,1] $变换到$ [-0.5, 0.5] $，但是`Flow`节点将`Negate`节点放在了`Flow Direction`前面，这意味着传入的`Flow Direction`并不会被取反，而是直接加上了`0.5`。

**为了抵消该错误计算，我们需要在传入`Flow Direction`前先对其减去`0.5`。**

我们还需要注意的是，我们需要关闭`FlowMap`的压缩，因为Unity使用的`DXT/BC`等压缩方式均属于块压缩，即将纹理图分成许多`4x4`的像素块，然后在每个像素块中提取出2个最主要的颜色，其余的14个像素将会通过插值的方式来得到，以此来节约内存。对于普通的图片来说肉眼并不能看出区别，但是我们一旦开启了`FlowMap`的压缩，就会触发严重的**块效应**（见数字视音频技术），即相邻的两个`4x4`像素块之间可能出现明显的断层，毕竟普通的贴图只是用于展示颜色，但是`FlowMap`的像素是用来表示方向的，更易于被察觉。

**因此，我们必须关闭`FlowMap`的压缩以防止块效应。**

# 交界处边缘光`Depth Fade`
这里的边缘光指的是球体与地面交界处的边缘光，并不是球体自身的边缘光，因此并不能直接通过菲涅尔算法求出。我们需要想办法获得球体与地面交界处的区域。

由于我们使用的是半透明的球体，因此并不会开启深度写入，那么我们就可以通过比较当前像素的深度和背景（地面）像素的深度之间的差值来获得交界处的区域，毕竟交界处的差值为`0`。

`ASE`为我们提供了一个 **`Depth Fade`节点用于直接获取当前像素与背景像素之间的差值**，我们可以通过调整`Distance`的大小来调整`Fade`区域的大小。使用该节点的前提是当前的物体是半透明物体，并且该节点是通过深度图来获取背景像素的深度的。我们在《入门精要》中曾学习过，摄像机的深度图是通过场景中所有的物体的`ShadowCaster Pass`来获取的，**因此如果我们关闭了场景中的灯光，Unity就会停止获取深度图。为了该情况，我们需要使用`C#`脚本来手动开启深度纹理**，即《入门精要》中曾提到过的`Camera.main.depthTextureMode |= DepthTextureMode.Depth;`

# 双面显示
要开启双面显示，我们只需要使用两个材质球，一个先渲染背面，另一个后渲染正面，**我们可以通过在`ASE`中创建一个`CullMode`枚举来避免使用两个`Shader`文件：**

我们可以创建一个一维变量，将其公开为`Properties`，并勾选`Auto-Register`，然后在最下方的`Attributes`菜单中勾选`Enum`，表明该变量属于枚举类型，然后在下方的`Enums`菜单中，将`Mode`调整为`Use Engin Enum Class`，然后即可在下方的`Class Name`中选择`UnityEngine.Rendering.CullMode`，最后回到表面着色器主面板中，点击`CullMode`最右侧的小黑点来切换选项，然后即可在下拉菜单中选择我们刚刚自定义的`CullMode`。
