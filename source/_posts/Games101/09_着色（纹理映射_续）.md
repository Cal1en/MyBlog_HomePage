# 1 重心坐标插值

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432.png]]

我们可以使用三角形的三个顶点的坐标来表示三角形内部的任意一点 $(x,y)$：
$$(x, y) = \alpha A + \beta B + \gamma C$$
其中 $\alpha + \beta + \gamma = 1$ ，同时 $\alpha、\beta、\gamma$ 均为非负数（当它们之中出现负数时表示三角形外部的点）。

> 从上式中也不难看出我们只需要使用 $\alpha、\beta、\gamma$ 中的任意两个即可表示 $(x,y)$ ，毕竟这是一个二维平面上的点。

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-1.png]]

我们也可以通过三角形的面积比来计算出 $\alpha、\beta、\gamma$ ，如上图所示：
$$\begin{align*}
\alpha &= \frac{A_A}{A_A + A_B + A_C} \\
\beta &= \frac{A_B}{A_A + A_B + A_C} \\
\gamma &= \frac{A_C}{A_A + A_B + A_C}
\end{align*}$$

- **重心坐标**

  重心坐标的表示方法如下所示：
  $$\begin{align*} (\alpha, \beta, \gamma) &= \left( \frac{1}{3}, \frac{1}{3}, \frac{1}{3} \right) \\ (x, y) &= \frac{1}{3}A + \frac{1}{3}B + \frac{1}{3}C \end{align*}$$
![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-2.png]]

将重心与三角形的三个顶点相连接，得到的三个小三角形面积恰好相等，即**重心能够将三角形面积均分为三份。**

三角形中任意一点 $(x,y)$ 的表示方法如下所示，该结果可以通过叉积得出，即**叉积的绝对值表示两个向量所构成的平行四边形的面积：**

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-3.png]]

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-4.png]]

于是我们就可以使用上述坐标的表示方法来对三角形内部的点的各种属性进行插值：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-5.png]]

> 虽然这种插值方法叫做重心坐标插值，但实际上与三角形的重心并没有什么关系。我们只是像计算三角形重心一样，通过三角形的三个顶点与对应的权重来描述三角形内部的点而已，并使用该权重计算插值的结果。

还要注意的是，三角形中的某个点在经过投影变换前后的重心坐标表示并不一定相同，即权重不一致，因此我们**应当在投影变换前就完成插值相关的计算**，或者将二维屏幕上的点通过投影逆变换到三维空间中再进行插值计算。

# 2 纹理放大 Texture Magnification 纹理过小

如果屏幕分辨率很大而纹理分辨率很小应该怎么处理？

> *pixel* 指的是屏幕/画面上的一个像素，*texel* 指的是纹理中的一个像素，又称为纹理元素/纹素。

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-6.png]]

## 2.1 最邻近采样 Nearest

指的是屏幕上的像素在计算对应的纹素时直接四舍五入计算坐标，因此会有多个像素指向同一个纹素，进而形成像素化的画面。

## 2.2 双线性插值 Bilinear

为了避免多个像素映射到同一个纹素上，我们引入了双线性插值：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-7.png]]

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-8.png]]

所谓双线性插值，指的就是**水平与竖直两个方向上的插值**合成得到的结果，两个方向的插值顺序可以调换。以先水平后竖直为例，水平方向上先分别计算出上方两个像素与下方两个像素各自的插值结果，然后将这两个插值结果作为竖直方向上的两个端点再进行插值。

## 2.3 双三次插值 Bicubic

> 不是三线性插值！

取周围的 16 个纹素进行插值。

# 3 纹理缩小 Texture Minification 纹理过大

如果屏幕分辨率很小而纹理分辨率很大应该怎么处理？该问题远比纹理过小更加严重，如下图所示：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-9.png]]

近处将会出现很明显的锯齿，远处则会出现摩尔纹，这同样是由**走样**导致的：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-10.png]]

上图左侧表示近处的采样，屏幕上的像素（蓝点）映射的纹素很少，对应**纹理放大**现象，因此会出现最邻近采样的锯齿；而远处的像素将会覆盖非常多的纹素，导致无法准确采样，产生错误的低频图案，进而出现摩尔纹，对应**纹理缩小**现象。

在光栅化部分，我们曾提到可以通过超采样来缓解走样带来的问题，但是超采样的性能消耗很大——原先我们只需要对屏幕上的一幅画面进行超采样，但这里我们需要对屏幕上的每个像素在其对应的纹理区域内进行**多次采样**并求平均值。

对屏幕上的画面进行超采样是一种“实时”的操作，因为画面上的内容是未知的，但是纹理则是已知的，换句话说，如果我们能够**尽可能提前计算纹理中这些区域的多次采样平均值**，而后在采样时直接获取对应区域的平均值，即可省去多次采样带来的性能消耗，这便是 ***Mipmap*** 的基本思想。

> 该问题属于范围查询问题中的平均查询，与其相对应的是点查询问题，即类似求出某个位置的值（e.g. 双线性插值）

## 3.1 Mipmap

快速、近似、正方形范围的范围查询。

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-11.png]]

- 层数：$0 \sim \log_2 n$ ，其中 $n$ 为原图分辨率。 
- 存储量：$1 + \frac{1}{4} + \frac{1}{16} + \frac{1}{64} + \cdots = \frac{4}{3}$ （各级纹理相加后的存储量仅仅是原纹理大小的 $\frac{1}{3}$ ）

- **计算屏幕像素在纹理上的覆盖区域**

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-12.png]]

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-13.png]]

我们首先查询当前屏幕像素以及其上方与右侧的像素的 uv 坐标；然后计算当前像素的 uv 坐标点与其上方与右侧的像素的 uv 坐标点之间的距离，并取两个距离中的最大值，其计算公式如下：
$$L = \max \left( \sqrt{\left(\frac{du}{dx}\right)^2 + \left(\frac{dv}{dx}\right)^2}, \sqrt{\left(\frac{du}{dy}\right)^2 + \left(\frac{dv}{dy}\right)^2} \right)$$
该公式主要通过计算在屏幕空间的 $xy$ 方向上移动 1 pixel，对应纹理空间在 $uv$ 方向上移动了多少 texel 来计算距离。

而后，我们就可以用该距离值作为当前像素在纹理中覆盖区域的边长，进而**将覆盖范围近似为一个正方形**，如下图所示：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100432-14.png]]

- **计算所需的 Mipmap 层级**

  如果我们计算出来的边长为 1，即当前像素在纹理空间中的覆盖范围恰好为 1 texel，此时我们只需要采样 level 0 即可，因为一个像素正好对应一个纹素；如果我们计算出的边长为 2，也就是一个像素对应 2x2 个纹素，那么我们就需要 level 1，因为我们需要 2x2 个纹素的平均值，以此类推，我们可以得到计算所需 Mipmap 层级的公式：
  $$\text{Mipmap level} ~ D = \log_2 L$$
  同时需要注意的是，哪怕我们计算出了所需的层级，我们也还需要在对应的层级上应用**双线性插值/双三次插值**，因为计算出的覆盖范围中心不一定落在某个纹素的中心。

- **三线性插值**

  显然我们计算出的层级 $D$ 很大概率不是整数，结果可能会落在两个层级之间。针对这种情况，我们首先需要先在相邻的两层中计算双线性插值，计算出两个层级上的插值结果后，然后再通过 $D$ 的小数部分再计算两个层级结果之间的插值，该过程被称为**三线性插值**。

  三线性插值保证了在各 Mipmap 层级之间的结果连续性。

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100433.png]]

## 3.2 各向异性过滤 Anisotropic Filtering (Ripmap)

但是三线性插值的缺点在于，其覆盖范围始终近似为一个正方形，但是屏幕像素映射的区域肯定不一定是一个正方形，覆盖范围会出现各种长宽不一致的情况，如下图所示：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100433-1.png]]

如果覆盖范围的长宽差距过大，此时使用两个距离之间的最大值的话，就会导致计算出的正方形覆盖面积远大于真实覆盖面积，从而导致使用更高层级的 Mipmap，导致结果模糊，我们称之为 *Overblur*。

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100433-2.png]]

各向异性过滤则是构造了一系列长宽比例不同的纹理图，我们称之为 *Ripmap*，便于在覆盖区域为矩形时进行近似采样，从而得到更好的结果：

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100433-3.png]]

![[img/Games101/09/09_着色（纹理映射_续）-20261014-100433-4.png]]

我们在游戏中遇到的“各向异性 2x 4x 8x 16x”等指的就是各向异性过滤最高允许使用的长或宽被压缩了 $n$ 倍的纹理。显然，各向异性过滤的 *Ripmap* 需要使用更多的内存空间，最后收敛于原存储量的四倍（增加三倍）。因此**各向异性过滤的不同等级对游戏性能的影响没有太多差异。**
